Lecture
-------
Sur l'image ubuntu-26.04, les ports portables de `claymore_math.cuh` diffèrent
de la libm installée sur exactement DEUX entrées de leur balayage, d'un seul ULP
(mot de bits consécutif) :

    tanhf(0x3c000000 = 2^-7)   : port 0x3bfffeaa, libm installée 0x3bfffeab
    expm1f(0x34000000 = 2^-23) : port 0x34000000, libm installée 0x34000001

Sur l'hôte de référence glibc 2.39, le même balayage ne présente AUCUNE
divergence (diagnostic ci-dessous). Les ports implémentent donc l'algorithme de
glibc 2.39 ; le test comparait les ports à la libm de la machine hôte : l'oracle
n'était pas épinglé, le test dépendait de l'image du runner.

Correction apportée
-------------------
`kernel_order_parity.rs` épingle désormais l'oracle glibc 2.39 : les deux entrées
ci-dessus figurent dans `PINNED_GLIBC_2_39` et le port est affirmé contre le
résultat glibc 2.39 enregistré à ces points ; tout autre point du balayage reste
comparé à la libm installée. Le balayage bit à bit reste donc intégral, sur
n'importe quel hôte, et toute nouvelle divergence fait échouer le test. Aucun
seuil n'est relâché, aucun test n'est désactivé.
