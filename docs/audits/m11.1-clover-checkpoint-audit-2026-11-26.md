Conséquences pour M11.2, sans conséquence sur la validation :

1. **Le FP32 n'existe que comme état d'exécution SSM/GDN**, jamais comme poids stocké : un cast FP32

2. `conv1d.weight` `[8192, 1, 4]` (noyau causal 4) et `conv_right_weight` `[8192, 1, 3]` (branches
   droites du sidecar) sont **deux tenseurs distincts** : l'adaptateur ne doit pas les fusionner ni
   déduire l'un de l'autre.
3. Les 243 dernières lignes de `embed_tokens`/`lm_head` sont injoignables par le tokenizer (§ 9) :
   **ne jamais tronquer la tête**, la dimension 248 320 est contractuelle.
4. Les experts sont déjà **empilés** par couche : pas de dé-interleaving à prévoir au chargement.

## 10. Correctifs intégrés avec le présent rapport

Deux corrections **de fiabilité des outils d'audit** accompagent la publication. Elles ne touchent ni
l'architecture Clover, ni la révision épinglée, ni aucun chemin d'exécution.

1. **Constantes de digest épinglées** dans `crates/claymore-model-clover/src/config.rs` :
   `CONFIG_SHA256` et `INDEX_SHA256`, plus `MODEL_ID` / `CONFIG_REVISION` existants. Les valeurs sont
   **égales aux empreintes calculées sur les octets bruts de la release** (§ 5), et sont ré-exportées
   depuis `lib.rs`.
2. **Porte fail-closed dans l'outil d'audit** `src/bin/inspect_checkpoint.rs` : l'empreinte de
   `config.json` est calculée et comparée **avant** son analyse (`config.json digest mismatch:
   expected …, got …`), l'empreinte de l'index est comparée à `INDEX_SHA256` après lecture de
   l'inventaire, et l'outil publie `config_sha256=…` dans sa sortie.

### Démonstration des portes (transcript publié)

`m11.1-gate-negative-tests-2026-11-26.log.txt`, produit par
`scripts/m11.1-gate-negative-tests.sh <checkpoint>`. Quatre essais, aucun octet de payload copié ni lu :

5. seulement ensuite, `verify_pinned_asset_hashes` (les 28 empreintes de payload).

Un index falsifié est donc rejeté **avant le moindre octet de payload haché**.

Contrôle positif de la chaîne de configuration : `CloverConfig::from_json` + `validate_pinned` sur les
octets bruts de la release valide **45/45 clés** identiques à `docs/audits/fixtures/clover-config.json`.

## 14. Reproductibilité

```bash
# snapshot epingle (revision 4b0402b65e523d0183a14c431955438714cb16ff)
CKPT=<repertoire-du-snapshot-4b0402b>
cd <racine-du-depot>
cargo build --locked -p claymore-model-clover --bin inspect_checkpoint

# 1. porte d'authentification : table epinglee extraite du code, 28 empreintes, puis deux executions
docs/audits/scripts/m11.1-run-checkpoint-audit.sh "$CKPT"

# 2. demonstration fail-closed des portes de digest (T0-T3)
BIN=target/debug/inspect_checkpoint LOG=m11.1-gate-negative-tests.log.txt \
  docs/audits/scripts/m11.1-gate-negative-tests.sh "$CKPT"

# 3. re-verification des preuves publiees
cd docs/audits && sha256sum -c m11.1-checkpoint-2026-11-26-logs.sha256 && cd <racine-du-depot>

# 4. audit tokenizer / gabarit (Python 3.12, transformers 5.19.0, jinja2 3.1.6, sans PyTorch)
python3 docs/audits/scripts/m11.1-tokenizer-audit.py "$CKPT" tokenizer-audit.json
python3 docs/audits/scripts/m11.1-chat-template-audit.py "$CKPT" chat-template-fixtures.json

  chat-template-fixtures.json docs/audits/fixtures/clover-tokenizer-fixtures.json
```

Les commandes 1 et 2 ne demandent que le snapshot et le binaire ; la commande 3 ne demande que le
dépôt. La commande 4 régénère le dump brut et le fichier de fixtures publiés. Aucune de ces commandes
n'alloue de VRAM ni ne charge un tenseur de payload.
