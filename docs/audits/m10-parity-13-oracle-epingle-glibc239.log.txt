2. Refutation : « ces deux entees sont les seules divergences »
---------------------------------------------------------------
Le journal 12 et la section 7.4 du rapport affirmaient que, sur l'image du
runner, les deux entrees epinglees etaient « les seules divergences de tout le
balayage ». C'est FAUX, et la raison est technique : l'assertion est a
l'interieur de la boucle du balayage, donc le test s'arrete a la PREMIERE
divergence rencontree. Deux tests en echec donnaient donc deux divergences
observables, pas deux divergences existantes. En retirant ces deux points, la
recherche a montre les suivantes (tanhf(-2**-7), puis expm1f(1.0)) - et rien
ne dit que la liste s'arrete la.

La formulation d'origine est conservee ici telle quelle, avec sa refutation :
la comparaison port <-> libm installee n'est pas une comparaison a deux points
mais a plusieurs centaines de milliers, et son issue depend de l'image du
runner.


3. Correction : le contrat est epingle a l'oracle, plus a l'hote
----------------------------------------------------------------
Le verrou de 85f7772 (R2) comparait encore le port a la libm installee sur
tout le balayage, sauf deux points. Cet oracle-la est deplace par l'image du
runner, donc le contrat etait conditionne a la machine. Nouveau contrat, dans
crates/claymore-model-gemma/tests/kernel_order_parity.rs :

  - palier 1, sur TOUTE machine : le port doit reproduire les resultats de
    glibc 2.39 publies dans trois tables de reference versionnees
    (tests/data/glibc_2_39_expf.bin, glibc_2_39_expm1f.bin,
    glibc_2_39_tanhf.bin) ;
  - palier 2, seulement si la libm installee passe la sonde des deux sentinelles
    (autrement dit si l'hote EST glibc 2.39) : le port doit de plus egaler la
    libm installee sur TOUTES les entrees balayees, epinglees ou non. C'est ce
    qui garde le pas dense sous contrat la ou les tables ne vont pas ;
  - hors hotes-oracles, le palier 2 est ignore avec une ligne sur stderr (le
    saut n'est pas silencieux ; un binaire de test capture ce flux, donc la
    ligne n'est visible qu'avec --nocapture, ce que le job ne fait pas) et le
    diagnostic ignore
    report_divergence_against_installed_libm publie le jeu de divergence ;
  - les tables ne sont regenerables que sur un hote-oracle : le test ignore
    regenerate_glibc_2_39_reference_tables refuse toute machine dont la libm
    differe des sentinelles.

Aucune tolerance n'est relachee, aucune entree retiree, aucun test desactive.

Decouverte annexe pendant cette correction : les grilles d'exposant du balayage
construisaient leur mantisse par `(m * 0x40000) & 0x800000`, ce qui ne produit
que DEUX mantisses distinctes par tranche d'exposant (le masque capturait le bit
de signe pour m >= 32, et m / m+32 collisionnaient). Le masque corrige
`& 0x007f_ffff` en donne 32. Le nombre d'entrees BALAYEES (poussees) est
inchange, le nombre d'entrees DISTINCTES non :
