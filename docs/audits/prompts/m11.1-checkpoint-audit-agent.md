# Agent handoff — M11.1 audit of the pinned Clover checkpoint

## Mission

Execute the remaining CPU-only M11.1 verification against the exact public Clover release snapshot. Return reproducible evidence for the checkpoint inventory, all 28 Safetensors SHA-256 values, raw metadata/code hashes, and tokenizer/chat-template behavior.

This is an audit task, not a model implementation task. Do not start M11.2, do not implement a forward pass, and do not use CUDA or the RTX 5090.

## Immutable source

- Repository: https://huggingface.co/Diffuspace/Clover-35B-A3B-Preview
- Required revision: 4b0402b65e523d0183a14c431955438714cb16ff
- Model: Diffuspace/Clover-35B-A3B-Preview
- Required disk headroom: at least 90 GB free before download (checkpoint payload is about 69.3 GB, plus cache and report space).
- Required runtime: CPU only; no CUDA initialization, no device allocation, no inference.

Do not use main, a floating branch, or a later revision. If a local snapshot already exists, prove its revision before reusing it.

## 1. Obtain and identify the snapshot

Use the Hugging Face CLI (or equivalent Hub API) to download the exact revision into a dedicated local directory:

~~~bash
hf download Diffuspace/Clover-35B-A3B-Preview \
  --revision 4b0402b65e523d0183a14c431955438714cb16ff \
  --local-dir /data/models/Clover-35B-A3B-Preview-4b0402b
~~~

Record:
- resolved repository revision / commit;
- local path and filesystem type;
- free disk space before and after;
- every downloaded filename and byte size;
- any download error, missing file, or symlink/LFS/Xet issue.

Do not silently substitute files from a different revision.

## 2. Run the Claymore CPU-only checkpoint inspector

From a clean checkout of Claymore at the PR #53 head (or a checkout containing that exact code), run:

~~~bash
cargo run --locked -p claymore-model-clover --bin inspect_checkpoint -- \
  /data/models/Clover-35B-A3B-Preview-4b0402b
~~~

Then run the full streaming hash pass:

~~~bash
cargo run --locked -p claymore-model-clover --bin inspect_checkpoint -- \
  /data/models/Clover-35B-A3B-Preview-4b0402b --verify-sha256
~~~

These commands must remain CPU-only. The first inspects config, index and Safetensors headers without reading tensor payloads. The second additionally streams all 26 model shards and both GDN sidecars to verify the pinned Xet SHA-256 values; it must not materialize the checkpoint in RAM.

Capture complete stdout/stderr and exit codes. Do not mark the audit successful if either command fails.

Expected pinned facts to verify, not assume:
- 26 model shards and 2 GDN sidecars;
- index total size: 69,322,701,696 bytes;
- 30 GDN right-convolution tensors of shape [8192, 1, 3];
- 90 GDN softmax scalar tensors of shape [32];
- all model tensors match the pinned names/shapes/dtypes validator, including the stacked 256-expert parameters and one shared expert per layer;
- all 28 Xet SHA-256 checks pass.

If the tensor-schema validator reports a mismatch, do not weaken the validator to make the audit pass. Preserve the exact offending tensor name, shard, expected shape/dtype and actual shape/dtype, then compare against the pinned Python source and index. Report any real source/implementation discrepancy.

## 3. Calculate raw SHA-256 for every non-Xet source artifact

Calculate SHA-256 over the exact raw bytes in the downloaded pinned snapshot (not rendered HTML, decoded text, or normalized JSON). Include at least:

- README.md
- LICENSE
- ATTRIBUTIONS.md
- config.json
- generation_config.json
- tokenizer.json
- tokenizer_config.json
- chat_template.jinja
- configuration_clover_moe.py
- modeling_clover_moe.py
- sampling_clover_moe.py
- model.safetensors.index.json
- .gitattributes

Use a standard SHA-256 implementation (for example sha256sum) and record filename, byte size and digest. Do not substitute Git blob SHA-1, repository commit SHA, Xet object ID, or ETag for SHA-256.

Cross-check that the local config parses and that its architecture fields agree with the pinned Rust fixture. Report any byte-level or semantic difference; do not rewrite the upstream files.

## 4. Audit tokenizer and chat template

Use a Python environment with the pinned Transformers version 5.19.0 and compatible Tokenizers/Safetensors packages if available. Do not load model weights.

Inspect tokenizer.json, tokenizer_config.json and chat_template.jinja and run CPU-only tests that establish:

1. tokenizer class and vocabulary size;
2. token ID/string mapping for:
   - 248044 <|endoftext|>
   - 248045 <|im_start|>
   - 248046 <|im_end|>
   - 151669 <|mask|>
   - 248068 <think>
   - 248069 </think>
3. EOS and PAD behavior, explicitly distinguishing tokenizer EOS string from the model config and generation_config EOS ID/list;
4. <|mask|> is registered as a special token and is not accidentally split into ordinary tokens;
5. the documented remapping of token 151669 and removal of affected BPE merges is consistent with the tokenizer data;
6. chat template rendering for at least:
   - a simple user message with assistant generation prompt;
   - a system + user + assistant conversation;
   - thinking enabled and disabled if the template exposes that switch;
7. exact rendered strings and token IDs for each fixture;
8. the template is text-only and does not accidentally inject image/video/audio processor structures.

Do not infer tokenizer correctness from the config alone. Record all fixture inputs, expected/actual strings and IDs, package versions, and results.

## 5. Deliverables

Produce one concise but complete audit report containing:

- pinned revision proof;
- downloaded artifact inventory and byte sizes;
- full inspect_checkpoint output and exit codes;
- full streaming SHA-256 verification result for all 28 indexed Safetensors files;
- raw SHA-256 table for all non-Xet artifacts above;
- tokenizer/chat-template fixtures and results;
- all discrepancies, warnings, and environment limitations;
- explicit statement that no payload tensors were loaded, no forward pass was run, and no CUDA/GPU was initialized.

If all checks pass, provide a proposed patch for:
- adding raw non-Xet SHA-256 values to docs/audits/clover-upstream-manifest.md;
- adding corresponding pinned constants/verification for config and index where appropriate;
- recording tokenizer/chat-template fixtures and audit results.

Do not commit, push, change the PR draft state, merge, or alter the pinned revision without explicit authorization. Return the report and patch/diff for review.

## Stop conditions

Stop and report immediately if:
- the pinned revision cannot be proven;
- a file is missing or comes from another revision;
- a SHA-256 mismatch occurs;
- the checkpoint inspector reports unexpected tensor names/shapes/dtypes;
- the tokenizer mapping contradicts the pinned config or generation defaults;
- disk space is insufficient.

Never repair a mismatch by changing the expected hash, accepting an unknown tensor, loosening the pinned schema, or downloading from main.
