## 6. Side effects, network, GPU

**Writes outside its own output directory**
- `gen_golden_eager_moe.py` — worst offender: `OUT=golden_eager_moe` but it **copies `moe0_{router_logits,topk_weights,topk_indices}.bin` into `golden_eager/`** and **rewrites `golden_eager/manifest.json`** (`shutil.copyfile` + `json.dump(MANIFEST)`) after its self-gate. Directly violates finalization-contract criterion 1 ("refuser d'écrire dans un répertoire de dorées existant", `docs/audits/m10-cpu-finalization-contract.md:52-56`).
- `gen_routers.py`, `gen_vision.py`, `gen_vision_stages.py`, `gen_decoder_stages.py` — `OUT` **is** the approved golden directory `golden_eager/`: they append tensors into it and rewrite `golden_eager/manifest.json` in place (non-idempotent manifest merge; re-running silently re-pins).
- `gen_golden.py` / `gen_golden2.py` — write `golden/`, and `gen_golden2.py` **reads and re-emits** `golden/manifest.json` into `golden/manifest_direct.json`.
- `gen_encoder_parts.py` — writes into `golden_stages/` (another script's dir) with a *separate* manifest.
- `add_raw_fixture.py`, `extract_fixture.py` (and the sibling `fix_test_literals.py`) — write **into the repo**: `/home/sjteb/projets/Claymore/crates/claymore-tensor/src/aten_topk.rs`. One-shot string codemods with `assert anchor in text`; re-running `add_raw_fixture.py` duplicates the const.
- `get_tensor.py` — writes a `.npy` to any caller-supplied path (`sys.argv[2]`).

**Network at runtime**: none. Every `from_pretrained` / `AutoTokenizer.from_pretrained` target is the local directory `/tmp/opencode/m10/checkpoint` (or a fixture `.bin`); no repo ids, no `revision=`, no `datasets`/hub calls in the 16 audited scripts. The only network dependency is the **initial checkpoint download** (see §3) — and, for `dg/`-based runs, the venv itself (transformers from git). `[INFERENCE]` transformers may still touch the hub for anonymous telemetry/`HF_HUB_OFFLINE` default checks unless `HF_HUB_OFFLINE=1` was exported; nothing in the logs shows hub traffic.

**GPU**: none. `grep cuda|CUDA|\.to\(|device_map` over the 13 model-running scripts → only `device_map="cpu"`; `torch 2.15.0+cpu` has no CUDA backend at all; docstrings state `CUDA_VISIBLE_DEVICES=""` was exported by the launcher. The `gpu_*.log` files at the workspace root come from the **Rust/CUDA hardware slot**, not these scripts.

**Other reproducibility hazards for a versioned generator**
- No `torch.set_num_threads` / `OMP_NUM_THREADS` / `MKL_NUM_THREADS` pinning anywhere → BF16 GEMM reduction order is thread-count-dependent (the campaign itself documented this as root cause #1, `m10-cpu-campaign-2026-11-23.md:345-352`).
- Hardcoded absolute paths in all 16 scripts (`/tmp/opencode/m10/...`) plus dependency on the agent-only file `/tmp/opencode/m10/all_headers.json` (`get_tensor.py`).
- No `torch.use_deterministic_algorithms`, no `torch.manual_seed` in the fixture-consuming scripts (they inherit fixtures from disk instead — correct, but the fixture provenance chain is only implicit).
- `probe_layer_inputs.py`, `gen_vision*.py`, `gen_decoder_stages.py` reshape FP32 fixtures back to `int64` (`astype(np.int64)`) — token ids survive only because they are ≤ 2²⁴; `prompt_ids` contains `236881`, which is safe, but the round-trip is dtype-lossy by construction.
- `check_decoder_rerun.py` and `reference_self_reproducibility.py` still carry the **invented prompt ids** `[2,1449,4470,2927,9776,2312,2]` instead of the golden `[3689,563,506,529,7001,236881]` — the exact defect recorded in `m10-cpu-campaign-2026-11-23.md:159-166` ("ids inventés … incomparable"); the fix was applied to `gen_decoder_stages.py`, not to these two.
- `golden_cpu.rs:4` header comment still claims the golden files are "produced by `gen_golden.py` in `/tmp/opencode/m10/golden`" while `golden_cpu.rs:19-20` sets `GOLDEN`/`STAGES` to `/tmp/opencode/m10/golden_eager` — stale doc.

**Rust-side counterpart (who writes `rust_vision/` / `rust_decoder/`)** — not the Python scripts: `crates/claymore-model-gemma/tests/golden_cpu.rs` under env knobs `M10_DUMP_RUST_VISION` (`golden_cpu.rs:499,501,513`) and `M10_DUMP_RUST_DECODER` (`golden_cpu.rs:588,618,630,648`). Consumers of the golden dirs: `golden_cpu.rs` (`GOLDEN`/`STAGES = golden_eager`), `golden_cpu_layer_bisect.rs` (`GOLDEN = golden_eager`, `LAYERS = golden_layers`, reads `enc_in_{L}` at lines 83/106, "Reads `golden_eager` and `golden_layers` read-only; it never repins them" at line 14), `hardware_m10_generation.rs:27` (`GOLDEN = golden_eager`); checkpoint root comes from env `CLAYMORE_M10_CHECKPOINT` (`real_checkpoint.rs:19`, `hardware_m10_streaming.rs:21`).
